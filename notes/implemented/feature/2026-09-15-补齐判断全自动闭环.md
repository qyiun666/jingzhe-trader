# 决策档案: 补齐"判断全自动 + 人只执行"闭环 —— 盘中卖出 / 加仓 / 不买说明

Status: implemented

## Problem

用户口径（2026-09-15）：买卖判断由系统自动出、人只在券商 App 执行、邮件是唯一交付。
按此口径核代码，发现三处缺口与两个 bug：

1. **盘中只盯止损**：`intradayScan` 每 5 分钟只判"现价 ≤ 成本×(1−止损线)"（`dayparts.go` 旧 `stopLossTickets`），
   止盈/移动止盈只在 16:30 算 → 某只冲到 +15% 当天不会提醒。
2. **"追加"做不到**：风控硬拒已持仓标的（`manager.go` 的 `RuleAlreadyHolding`），且 `buyDecisions`
   根本拿不到持仓（`Generate` 读了 `positions` 却不传给它），LLM 不知道手里有什么、无法建议加仓。
3. **"没机会"不吭声**：关闸/0 候选时 M1 不发（`NO_PENDING_TICKET`），用户看不到"为什么没买"。
4. **Bug A（移动止盈形同虚设）**：`position.high_price` 是移动止盈的回撤基准，但它只在
   买入成交时写入（`ticket/ledger.go` applyPosition），日线/盘中都不更新 → "高点"永远停在买入价。
5. **Bug B（早上看不到指令）**：指令单 `trade_date` 是生成日（前一晚 16:30），而 M2 计划邮件
   按 `trade_date=今天` 查（`ListActiveTickets`）→ 第二天早上那封邮件永远是空的。

## Decision

三处补齐 + 两 bug 修复，全部不引入新依赖、不改执行方式（仍人工下单）：

- **盘中卖出（R1）**：`signal.EvalPriceRules` 只跑价格型三规则（止损>移动止盈>止盈）；
  `intradayScan` 先 `RaiseHighPrice(现价)` 抬升期间高点（只升不降，SQL `WHERE high_price<?`）再评估；
  沿用 `pendingSellSet` 去重、`notifySell` 发 M3；告警码 `INTRADAY_STOP`→`INTRADAY_SELL`。
  收盘流水线另加 `raiseHighWatermarks(当日收盘)` 作兜底（盘中行情缺失时也更新）。
  排名淘汰/大盘恶化**不接盘中**：TopN 只在 16:30 内存里（不落库），盘中拿不到就不能伪造；
  大盘 MA60 用收盘价现算，盘中重算会把日频熔断变成分钟级抖动。
- **加仓（R2）**：`risk.AccountState` 增 `HeldMV`；`CheckBatch` 把"已持有"从拒绝改为**加仓路径**——
  跳过 `RuleMaxPositions`（不占新名额）、单票额度改为 `单票上限 − 现有敞口`（新增 `RuleSinglePositionFull`）；
  `BuyIntent` 语义不变（一笔=一个方向一份量）。持仓经 `buyDecisions` 传入 `BuyRequest.Holding`，
  `blocks.go` 的 `holdingBlock` 把成本/浮盈亏/期间高点/可加额度渲染进 prompt，
  `prompts.go` 的 `decisionSystem` 说明"已持有=加仓、不占名额、额度上限"。
  只有仍进 TopN 的持仓可加（跌出者走既有排名淘汰），两者自洽。
- **不买说明（R3）**：`screenCandidates` 的 SCREEN_EMPTY 文本改为 `emptyReason`（关闸→"大盘在 MA60 下方…
  非故障"；否则点名筛空的那一级）；`buildTickets` 补 `NO_TICKET_FROM_CANDIDATES`（有候选却 0 指令）。
  日报/计划邮件引用 `tradeConclusion`（读 `job:evening_pipeline` 最近一行的 Detail，跨日回落）。
- **Bug B 修复**：新增 `TradeRepo.ListActiveUnexpired(cutoff)`（活跃 + `valid_until ≥ now`，不按
  `trade_date` 过滤），M2 的 `todayPlanLines` 改用它。新增 `TraceRepo.LatestBySubject` 支撑跨日结论引用。
- 邮件模板：`RenderM2` 增「昨日收盘结论」段、`RenderM5` 增置顶「今日结论」段（空串不渲染）。

## Alternatives considered

- **盘中接全部五条规则**：会把"大盘跌破 MA60 清仓全仓"变成实时熔断，波动大时频繁触发；且 TopN 不落库，
  盘中排名淘汰无据。弃（用户确认只接价格型三条）。
- **持久化当日 TopN 以便盘中做排名淘汰**：为一条规则新增一张表与一整套保留策略，代价远超收益。弃。
- **允许加仓非 TopN 持仓**：与"跌出 TopN 就卖"直接冲突（一边卖一边加）。弃（用户确认只加 TopN）。
- **`HeldMV` 用市值口径**：与 `PositionsMV`（成本口径）保持一致更简单，且单票上限本来就是风控度量，
  成本口径更保守。弃市值口径。
- **关闸日/空表也发 M1**：增加每日邮件量而信息量低；改为写进必发的 M2/M5（用户确认）。

## Consequences

- 行为变更 1：盘中会因止盈/移动止盈（不再只是止损）出 M3 卖单，用户需在当天执行。
- 行为变更 2：LLM 可对仍在 TopN 的持仓加仓；`already_holding` 不再出现，取而代之的是
  `single_position_full`（额度用尽）。新仓行为逐字段不变（`manager_test.go` 原用例仅把"重复持仓"改为"加仓额度已满"）。
- 行为变更 3：日报新增置顶「今日结论」，计划邮件新增「昨日收盘结论」；M2 现在能看到跨日未过期指令（修 Bug B）。
- 移动止盈从此真正生效（高点随行情抬升），实盘可见的回撤止盈触发会明显增多，属修复而非新策略。
- 实测：`go build ./... && go vet ./... && go test ./...` 全绿；真实库实跑 `run task intraday_scan`
  取到真实价（600519.SH 1272.75）、触发止损、建卖出指令单并落 `INTRADAY_SELL` 告警（M3/M6 仅因
  本机假 SMTP 凭据发送失败，属预期）。
- 相关档案：大盘门槛见 `notes/implemented/feature/2026-09-07-大盘门槛MA20换MA60.md`；
  本轮不改门槛口径，只是把价格型卖出接进盘中。
