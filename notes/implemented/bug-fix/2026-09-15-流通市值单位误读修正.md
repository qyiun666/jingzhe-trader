# 决策档案: 修正流通市值单位误读导致的可投池塌缩

Status: implemented

## Problem

`daily_basic` 的 `circ_mv` 被当作**千元**，`ToModelValuation` 里又除以 10 折算成万元：

```go
CircMvW: r.CircMv / 10.0,   // 注释：circ_mv 单位为千元
```

实测（2026-09-15，`trade_date=20260908` 原始返回 vs 已知市值）：

| 标的 | 原始 `circ_mv` | 真实流通市值 | 单位 |
|---|---|---|---|
| 000001.SZ 平安银行 | 22859896.93 | 2286 亿 | 万元 |
| 600519.SH 贵州茅台 | 163673183.9 | 16367 亿 | 万元 |

即该字段本来就是**万元**，不需要换算。除以 10 的后果是每个流通市值都比真实值小 10 倍，而门槛 `screen.min_circ_mv_w=500000`（注释与 PRD 都写明"50 亿"）实际只放行真值 ≥500 亿的票。

复算（2026-09-08 截面，`data/backtest/vals.csv.gz`，命令与口径可重现）：

| 口径 | 只数 |
|---|---|
| `circ_mv_w ≥ 500000`（50 亿）单门槛 | 2910 |
| 叠加完整硬门槛（50 亿 + 换手≥1% + 0<PE≤80 + 0<PB≤10） | **966** |
| 按缩小 10 倍的值过同一组硬门槛 | **94** |

即"50 亿"这个门槛单看放行约 2900 只，但选股漏斗还有换手/PE/PB 三道，真实可投池是 **94 → 966**（约 10 倍）——这才是本次修正对选股的实际影响面。

同一错误还经 `llm/blocks.go` 的 `/10000` 渲染进 prompt（"流通市值 228.6 亿" vs 真实的 2286 亿），把 10 倍失真的市值喂给买入决策者。

**发现路径**：IC 度量时按注释里的"50 亿"设门槛，结果单截面样本数从 709 掉到 388——这个不合理的中位数触发了对单位的口径核查，最终用原始 API 返回值与已知市值交叉验证定位。这条链路（建尺子 → 发现可投池异常 → 反查单位）正是"先建尺子"的价值。

## Decision

`ToModelValuation` 直接透传 `circ_mv`（万元），不再除以 10；同步修正 `RawValuation` / `DailyBasic` 的注释。

不改门槛数值：`500000` 万元 = 50 亿，与注释和 PRD 一致。修的是数据，不是阈值——反过来把门槛调成 `50000` 只会让注释与代码永久对不上，且把错误固化进配置。

## Alternatives considered

- **保留 /10、把门槛配成 50000**：让注释与 PRD 永久失真，且掩盖一个会在别处（LLM prompt、板块加权）继续显形的错误。弃。
- **只改注释不改代码**：数据仍然错 10 倍。弃。

## Consequences

- 换来：可投池从约 94 只恢复到约 966 只（10 倍），选股漏斗的流动性筛重获其设计意图；LLM 拿到的市值恢复真实量级（影响它判断"这笔钱相对市值是否过大"）；板块强弱排名按 `CircMvW` 加权的口径同时变得正确。
- 影响面：`CircMvW` 的消费者共三处 —— `screener.liquidityStage`（门槛，**修正**）、`llm/blocks.go`（prompt 展示，**修正**）、`screener.BuildReason`（理由文本，**修正**）；`screener.rankSectors` 的板块加权**不受影响**（它是 wsum/wtot 相对加权，统一缩放因子约掉）。
- 已落库的旧值不会自愈：需重跑一次 `run task daily`（本机开发库已重同步，`stock_basic.circ_mv_w` 现为真值）；生产库下次日频同步即覆盖（估值截面每日整批写）。
- 回测历史 CSV 同步修正：`data/backtest/vals.csv.gz` 按 ×10 就地改正（旧值 = 真值/10，修正为精确逆运算），并抽查与原始 API 一致。
- 回归锚点：`internal/tushare/decode_test.go` 用上表三个真实标的的原始值断言，并显式断言"值不等于 raw/10"，锁死该错误不会回来。
- 记一笔流程教训：这个错误在原实现里挂了很久没被发现，因为**没有任何断言把"入库值"与"真实世界量级"对上**——所有测试都在验证"转换函数被调用"，没验证"结果应该多大"。单位类缺陷只有靠与外部真值交叉验证才抓得住。
